# Working rules

1. **Think before coding.** Read the relevant code and state your plan before you edit anything.
2. **Keep it simple.** Make the smallest change that solves the problem. No new abstractions or dependencies unless the task needs them.
3. **Make surgical changes.** Touch only what the task requires. Don't refactor, rename or reformat unrelated code.
4. **Define success criteria and verify them.** Decide how you will know it works, then run the build and tests to prove it before you finish.
